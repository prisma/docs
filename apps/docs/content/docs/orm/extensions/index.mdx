Prisma 8 keeps its core small and adds everything else through packages. Two kinds exist:

- An **extension** adds a database capability: new column types, query operations, index types, and the migrations that install the underlying database feature. Vector search, geospatial data, full-text search, and typed JSON are all extensions. [Using extensions](/orm/extensions/using-extensions) walks through install, registration, and the first query.
- A **middleware** wraps every query your app sends: it can rewrite, block, observe, or answer a query before the driver runs. Caching, lints, and budgets are middleware. [How middleware works](/orm/middleware/how-middleware-works) explains the hooks.

Browse everything, with install commands and registration snippets, in the [extension directory](https://www.prisma.io/extensions). The tables below are generated from the same registry.

## Publish your own

Everything around the Prisma 8 core is an extension, including PostgreSQL support itself, so the same layout that ships pgvector is open to you. An extension pack is a versioned npm package with a `control` entrypoint for the config and a `runtime` entrypoint for the client. The [call for extension authors](https://www.prisma.io/blog/prisma-next-call-for-extension-authors) explains the layout, and the [authoring guide](/orm/middleware/authoring-custom-middleware) builds a middleware step by step.

When your package is on npm, [submit it to the directory](https://www.prisma.io/extensions/submit). The form validates the entry, checks that the package resolves on npm, and opens a pull request against the registry for a maintainer to review.
